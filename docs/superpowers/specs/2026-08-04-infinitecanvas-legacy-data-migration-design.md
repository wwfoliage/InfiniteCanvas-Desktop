# InfiniteCanvas 旧版用户数据迁移设计

## 背景

旧项目位于 `E:\InfiniteCanvas`，桌面版源码位于
`E:\codex\项目源码\InfiniteCanvas-Desktop\source`。已安装桌面版把可写用户数据存放在
`%LOCALAPPDATA%\InfiniteCanvas`，EXE 内只包含只读程序资源。

本次工作把旧项目的用户数据一次性迁入当前桌面版，同时保留桌面版已经产生的数据。迁移不修改旧项目，不把用户数据硬编码进 EXE，也不重新打包安装程序。

## 已确认数据

- 旧素材 161 个，约 320 MB；当前桌面版素材 5 个，双方没有同路径冲突。
- 旧画布 21 个；当前桌面版画布 1 个，双方没有同 ID 或同文件名冲突。
- 旧媒体预览 282 个；当前桌面版媒体预览 12 个，双方没有同路径冲突。
- 旧历史记录 29 条；当前桌面版历史记录 5 条，双方没有任务 ID、请求 ID或时间键重复。
- 旧素材库登记 52 条，包括 26 个角色、23 个场景、1 个物品和 2 个 MediaKit 视频。
- 旧提示词库比当前桌面版多 2 个自定义模板；双方共有的 10 个系统模板保留桌面版版本。
- 旧项目包含“默认项目”和“广告”；当前桌面版包含“默认项目”。
- 旧版和桌面版源码中的 7 个工作流文件 SHA-256 完全一致。

## 目标

1. 把旧素材、画布、历史、素材库索引、项目、提示词和可恢复的任务数据迁入桌面版。
2. 同 ID 但内容不同的记录全部保留，旧记录使用新 ID，并在显示名称后增加“（旧版）”。
3. 保持当前 API 配置、登录状态、当前画布、对话和其他桌面版数据不变。
4. 迁移过程可预检、可验证、可审计、可完整回滚。

## 非目标

- 不修改 `E:\InfiniteCanvas`。
- 不重新构建 EXE 或安装包。
- 不导入旧 API 密钥、API 服务商配置或全局应用配置。
- 不迁移调试文件、日志、WebView 浏览数据或空的旧 `output` 目录。
- 不新增通用的“导入旧项目”界面功能。

## 迁移架构

迁移使用一次性脚本，分为预检、备份、暂存、提交、验证和报告六个阶段。源目录始终只读，目标目录为 `%LOCALAPPDATA%\InfiniteCanvas`。

备份写入 `E:\codex\无限画布资料\迁移备份\<日期时间>`。迁移报告写入
`E:\codex\无限画布资料\迁移记录\<日期时间>`。报告只包含路径、数量、哈希、冲突决策和验证结果，不包含密钥或提示词正文。

## 数据处理规则

### 文件型数据

素材、画布和媒体预览先复制到暂存区，核对大小和 SHA-256 后再提交。当前检查未发现同路径冲突；若执行时出现新增冲突，相同哈希文件跳过，不同哈希文件使用带“旧版”和短哈希的唯一文件名，并同步更新受影响的 JSON 引用。

### 项目和画布

当前 `default` 项目保持不变。旧 `default` 项目生成新 ID，名称改为“默认项目（旧版）”；引用旧 `default` 的 20 个画布同步改用新项目 ID。旧“广告”项目 ID 唯一，直接加入；对应画布保持原关联。

### 素材库

当前素材库保持不变。旧素材库生成新 library ID，名称改为“默认资产库（旧版）”，其 52 条登记记录和分类结构完整保留。迁移后保持当前 active library 不变，用户可在素材库切换器中选择旧版素材库。

### 历史记录

旧 29 条与当前 5 条记录合并，按 `timestamp` 从新到旧排序。优先用 `task_id`，其次用 `request_id`，最后用时间戳和媒体 URL 组合作为去重键。当前预检结果为 0 条跨目录重复。

### 提示词库

保留桌面版的 10 个系统模板，只追加旧版独有的 2 个自定义模板。若执行时发现 ID 冲突但内容不同，旧模板生成新 ID，名称增加“（旧版）”。

### 其他运行数据

旧 `mediakit_tasks.json` 在目标不存在时迁入；`mediakit_settings.json` 当前与旧版哈希相同，保持目标文件不变。目标已有的 conversations、canvas media tasks、日志和 WebView 数据原样保留。

### 工作流

7 个工作流已经逐文件验证为相同，不复制、不重打包。桌面 EXE 继续从只读程序资源目录加载这些工作流。

### 敏感配置排除

以下内容不得从旧项目复制：

- `API\.env`
- `data\api_providers.json`
- `global_config.json`
- 任何日志、报告或临时文件中的密钥值

迁移前后对目标 API 配置文件计算 SHA-256，验证其完全未变。

## 安全与错误处理

迁移开始前确认 InfiniteCanvas 未运行；若仍在运行，脚本停止并提示用户手动关闭。任何正式写入前先完成目标数据的完整备份，并验证备份文件数量。

所有合并后的 JSON 先写入暂存区并重新解析。只有预检全部通过才提交。提交后进行完整验证；任一关键验证失败，脚本停止并从备份恢复目标数据。恢复后再次核对备份与目标的清单和哈希。

脚本应可重复运行：已迁移且哈希相同的数据不会再次复制，已经生成的旧版记录通过稳定迁移标记或映射表识别，避免重复导入。

## 验证与完成标准

在迁移期间没有其他新数据写入的前提下，预期结果为：

- 素材文件 166 个。
- 画布 22 个。
- 历史记录 34 条。
- 媒体预览 294 个。
- 项目 3 个：当前默认项目、默认项目（旧版）和广告。
- 旧版素材库可访问 52 条登记资源。
- 提示词模板包含当前 10 个系统模板和旧版 2 个自定义模板。
- 工作流保持 7 个，SHA-256 不变。
- 当前 API 配置文件迁移前后 SHA-256 不变。

静态验证通过后启动现有桌面 EXE，确认它仍以 PyWebView 桌面窗口运行，不打开外部浏览器或 CMD 窗口。界面抽查当前画布、旧画布、项目归属、素材缩略图、历史记录、提示词和 7 个工作流。

## 交付物

- 一次性迁移脚本和只读预检模式。
- 迁移前完整备份。
- 不含敏感信息的迁移报告和 ID 映射表。
- 静态校验结果与桌面应用抽查结果。
