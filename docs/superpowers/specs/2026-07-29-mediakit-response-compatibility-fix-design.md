# AI MediaKit 响应兼容与安全重试设计

日期：2026-07-29

## 背景

智能画布创建生成式画质增强任务时显示“创建 MediaKit 增强任务响应缺少 result”。

火山引擎当前 AI MediaKit 异步工具接口在创建成功时返回顶层 `task_id`：

```json
{
  "success": true,
  "task_id": "amk-tool-...",
  "request_id": "..."
}
```

现有后端只接受 `result.task_id` 或 `data.task_id`，因此把成功响应误判为格式错误。任务查询响应则把 `status` 放在顶层，把产物地址放在 `result.video_url`，同样需要同时保留顶层状态与嵌套结果。

## 目标

1. 兼容 AI MediaKit 当前顶层响应，以及已有的 `result`、`data` 包装响应。
2. 正确显示 HTTP 2xx 且 `success: false` 的业务错误。
3. 正确读取查询响应的顶层任务状态和嵌套视频地址。
4. 对本次因解析错误而失败的任务复用原 `client_token` 重试，使用官方幂等机制降低重复创建和重复计费风险。
5. 不在自动测试中调用真实收费接口。

## 非目标

- 不更换为 MediaKit CLI。
- 不修改画质增强参数、节点外观或保存目录规则。
- 不自动重新提交用户已经失败的任务；仍由用户点击“开始增强”触发。
- 不猜测或扫描云端任务列表来恢复未知任务 ID。

## 设计

### 1. 响应校验与解析

新增统一的响应载荷解析函数：

- JSON 必须是对象。
- HTTP 状态码大于等于 400 时，优先提取 `error.message`、`message` 或 `msg`。
- HTTP 2xx 但 `success` 明确为 `false` 时，按业务失败处理，并显示真实错误。
- 兼容旧式非零 `code`。
- 校验通过后返回完整顶层载荷，不提前丢弃 `status`、`task_id` 等字段。

另提供候选对象遍历逻辑，按顶层、`result`、`data` 顺序查找字段。

### 2. 创建任务

创建成功后从以下位置依次读取任务 ID：

1. 顶层 `task_id` 或 `id`
2. `result.task_id` 或 `result.id`
3. `data.task_id` 或 `data.id`

找到后写入本地任务记录并进入轮询。

### 3. 查询任务

查询响应保留完整载荷：

- 状态优先读取顶层 `status` / `state`，并兼容嵌套对象。
- 视频地址在顶层、`result`、`data`、`output` 中查找 `video_url` / `url`。
- 失败原因优先读取顶层或嵌套的 `message`、`error_message`、`error`。

### 4. 安全重试

前端仅在以下条件同时满足时复用当前节点保存的 `client_token`：

- 节点状态为失败；
- 没有远端或本地可轮询任务 ID；
- 错误属于响应解析兼容问题。

后端收到相同 `client_token` 时：

- 已有可查询任务或已完成任务：直接返回现有记录；
- 只有解析失败记录且没有远端任务 ID：允许使用同一 `client_token` 再次向上游提交；
- 其他失败类型保持原行为，避免无条件重复请求。

由于 MediaKit 的 `client_token` 用于幂等控制，如果第一次上游请求实际上已创建任务，再次使用同一值应返回同一任务，而不是新建计费任务。

### 5. 数据与日志

- 不记录 API Key。
- 本地任务记录可保存上游 `request_id`，用于后续排查。
- 解析失败错误不保存完整响应体，避免意外记录敏感内容；仅保留安全字段和清晰错误。

## 错误处理

- `success: false`：显示官方 `error.message`。
- 缺少任务 ID：显示“MediaKit 创建成功响应未返回 task_id”，而不是笼统的“缺少 result”。
- 查询完成但没有视频地址：保留现有明确错误。
- 安全重试仍失败：更新同一条本地任务记录，不创建无限重复记录。

## 测试

单元测试覆盖：

1. 顶层 `task_id` 创建响应。
2. `result.task_id` 和 `data.task_id` 兼容响应。
3. HTTP 2xx + `success: false` 错误解析。
4. 查询响应的顶层 `status` + `result.video_url`。
5. 同一 `client_token` 对解析失败任务的安全重试。
6. 已提交或已完成任务不会重复提交。
7. 现有本地上传、结果下载、重试保存测试继续通过。

测试全部使用模拟响应，不调用真实 MediaKit 接口。

## 验收标准

- 点击“开始增强”后，顶层 `task_id` 响应能够进入“已提交/处理中”状态。
- 官方业务错误以中文可读信息显示。
- 任务完成后正确下载视频并放入新结果节点。
- 对截图中这类解析失败再次点击时复用原 `client_token`。
- 自动测试不产生远端任务或费用。
