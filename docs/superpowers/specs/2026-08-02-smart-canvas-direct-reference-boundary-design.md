# 智能画布直接连线参考边界设计

## 目标

智能画布在生图或生视频时，只允许当前节点直接上游连线提供的图片和视频作为画布参考素材。更前面的祖先节点、旁支节点和未连线节点不得出现在“输入”来源的 `@` 候选中，也不得上传给模型。

资产库中由用户手动 `@` 的图片或视频属于明确选择，允许上传。当前节点已经显示在参考栏中的手动资产参考和自身编辑参考继续保留。

## 统一规则

参考素材分为三类：

1. 直接连线参考：仅取当前节点的直接入边，不递归遍历祖先节点。普通 API 模式读取 `input` 入边；需要工作流输入的模式按现有规则读取 `input` 和 `flow` 入边。
2. 手动资产参考：资产库手动 `@` 的媒体和已加入参考栏的资产允许使用，不要求画布连线。
3. 自身编辑参考：当前节点已有媒体、且现有生成模式需要把自身作为编辑输入时，保持原有行为。

画布中的其他素材，无论是否与直接上游节点存在更早的链式连接，只要没有直接连接当前节点，都不属于允许集合。

## UI 行为

输入来源的 `@` 候选只展示直接连线节点的图片和视频，并按 URL 去重。资产库标签仍展示资产库素材，不受画布连线限制。

链路 `A → B → C` 中，在 C 的输入来源打开 `@`：

- 展示 B 的媒体；
- 不展示 A 的媒体；
- 不展示任何未连线节点的媒体；
- 资产库标签仍可选择资产素材。

参考栏继续展示最终会上传的有效参考，确保 UI 与实际请求一致。

## API 请求边界

构建生图或生视频请求前，建立当前节点的允许参考集合：直接连线参考、自身编辑参考、手动资产参考以及资产库 `@` 引用。所有画布来源的提示词媒体标记都必须验证其 `nodeId` 是否属于直接上游节点；验证失败时只在提示词中保留 `@名称` 文字，不把对应媒体加入请求引用。

资产库 `@` 仅通过没有画布 `nodeId` 的资产标记识别，允许进入请求。带 `nodeId` 的画布素材必须来自直接连线，不能因为带有资产注册信息而绕过边界。最终引用仍遵循现有数量上限，并按 URL 去重，避免同一素材因直接连线和 `@` 同时出现而重复上传。

此过滤必须位于共享请求构建层，使生图和生视频共用同一规则，而不是分别在某个平台分支中实现。

## 兼容性

- 已保存提示词中指向祖先节点或已断开节点的旧 `@` 标记不会删除；运行时把它当普通文字处理，不再上传媒体。
- 资产库旧 `@` 标记即使没有平台注册 URI，只要没有画布节点来源，仍视为用户手动资产并允许上传。
- 现有手动移除/屏蔽参考、引用数量上限、图片与视频类型识别和 URL 去重逻辑保持不变。
- 不修改提示词文本上游传递规则，本次只限制媒体参考边界。

## 测试

增加针对共享引用逻辑的回归测试：

1. 链路 `A → B → C`：C 的输入 `@` 候选包含 B，不包含 A。
2. 未连线节点 D：C 的候选与请求均不包含 D。
3. 图片和视频：B 中两种媒体均可作为直接参考。
4. 资产库 `@`：未连线资产仍进入请求。
5. 旧祖先 `@`：提示词保留名称，但请求引用不包含祖先媒体。
6. 重复 URL：直接连线和资产 `@` 指向同一 URL 时只上传一次。
7. 生图与生视频：两种请求路径都使用同一过滤后的引用集合。

## 非目标

- 不改变文本提示词的递归或循环传递逻辑。
- 不改变资产库浏览、分类和注册流程。
- 不自动删除用户已保存的旧 `@` 标记。
- 不调整连线创建、删除和节点布局行为。
