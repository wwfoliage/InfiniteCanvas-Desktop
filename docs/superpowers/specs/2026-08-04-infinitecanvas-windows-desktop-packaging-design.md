# InfiniteCanvas Windows 桌面安装包设计

## 目标

将现有 FastAPI + 静态前端项目交付为 Windows 10/11 64 位桌面应用。用户双击 `InfiniteCanvas.exe` 后直接看到独立窗口，不打开外部浏览器，不显示 CMD 控制台。首版提供干净安装包，并支持以后通过更高版本安装包进行手动覆盖升级。

## 交付物

- `InfiniteCanvas-Setup-<VERSION>.exe`：Inno Setup 安装包。
- PyInstaller `onedir` 构建目录：用于验证和故障排查，不作为主要分发入口。
- 构建脚本、PyInstaller spec、Inno Setup 脚本和构建说明。
- 安装包 SHA256 摘要及敏感信息扫描结果。

## 架构

新增一个轻量桌面入口模块，负责启动本地 FastAPI 服务、等待服务就绪、创建 PyWebView 窗口，以及在窗口关闭时停止服务。FastAPI 仅绑定 `127.0.0.1`，端口由系统动态分配，避免固定端口冲突和局域网暴露。

PyWebView 使用 Windows WebView2 渲染现有 HTML、CSS 和 JavaScript。应用不会启动 Chrome、Edge 等外部浏览器。PyInstaller 使用 `--windowed` 的 `onedir` 模式生成无控制台程序，并显式收集静态资源和 Python 依赖。Inno Setup 将构建目录封装为标准安装程序，提供开始菜单、桌面快捷方式和卸载入口。

## 组件边界

### 桌面入口

- 创建独立事件循环和后台服务线程。
- 在 `127.0.0.1` 上选择可用端口并启动 Uvicorn。
- 服务就绪后打开 PyWebView 主窗口。
- 窗口关闭时请求 Uvicorn 正常退出，并设置超时兜底。
- 启动失败时显示原生错误对话框，并把详情写入日志。

### 路径管理

程序资源和用户数据必须分离：

- 只读程序资源：PyInstaller 构建目录中的 `static/`、`workflows/`、`CLI/`、`tools/`、`VERSION` 等。
- 可写用户数据：`%LOCALAPPDATA%\InfiniteCanvas`。
- 用户数据包括 API 配置、画布、素材、生成结果、历史、预览、任务记录和日志。

开发模式继续兼容仓库目录结构。打包模式通过统一的路径模块解析资源目录和数据目录，业务代码不直接依赖 PyInstaller 的临时路径。

### 构建与安装

- PyInstaller 使用 `onedir`，避免 `onefile` 每次启动解压造成的延迟和资源路径复杂度。
- 正式入口启用 `windowed/noconsole`；调试时保留可选的控制台构建方式。
- Inno Setup 使用稳定的应用标识符，后续版本覆盖安装到同一位置。
- 安装和卸载不得删除 `%LOCALAPPDATA%\InfiniteCanvas`，从而保留用户数据。
- 版本号以仓库 `VERSION` 为唯一来源，并写入 exe 和安装包文件名。

## 首次启动与升级

首次启动时创建缺失的用户数据目录和安全默认配置。安装包中不得携带开发电脑上的 `.env`、API Key、Token、Secret、画布、素材、历史或调试数据。

升级采用手动方式：发布更高版本安装包，用户下载后覆盖安装。程序文件被替换，`%LOCALAPPDATA%\InfiniteCanvas` 保持不变。首版不实现后台下载、自动安装或升级回滚。

## 外部依赖

- Windows 10/11 通常已包含 WebView2 Runtime；安装器负责检测，缺失时给出明确提示或运行随包提供的引导安装程序。
- Codex、Antigravity、即梦等外部 CLI 不嵌入干净安装包。相关功能仍要求用户在目标电脑单独安装并登录。
- 在线 API 功能需要用户首次运行后自行填写密钥。

## 错误处理与日志

- 正式版本不显示 CMD。
- 日志写入 `%LOCALAPPDATA%\InfiniteCanvas\logs`，不得记录完整密钥或敏感请求头。
- 启动失败、WebView2 缺失、服务超时和端口绑定失败必须显示可读错误提示。
- 正常关闭窗口时停止后台服务；异常退出不得留下长期驻留的子进程。

## 干净构建规则

构建输入采用白名单方式收集程序文件，并明确排除：

- `.git/`、`__pycache__/`、`*.pyc`、日志和临时文件。
- 所有 `.env` 和个人配置中的密钥字段。
- `assets/`、`output/`、`history.json` 中的当前内容。
- `data/canvases/`、`data/media_previews/`、任务记录、个人资源库及其他运行数据。
- 指向开发电脑路径的快捷方式和调试文件。

构建完成后同时扫描打包目录和最终安装包的展开内容，确认不存在被排除数据或已知密钥值。

## 验证标准

1. 在干净的 Windows 10/11 64 位环境安装并启动成功。
2. 双击程序只出现 InfiniteCanvas 桌面窗口，不打开外部浏览器，不出现 CMD。
3. 服务仅监听 `127.0.0.1`，固定端口被占用时仍能启动。
4. 主页面、画布、静态资源和核心 API 正常工作。
5. 关闭窗口后后台服务和子进程退出。
6. 首次运行能创建用户目录，重启后画布和配置仍存在。
7. 使用更高版本安装包覆盖升级后，用户数据保持不变。
8. 卸载程序文件成功，用户数据默认保留。
9. 自动化测试、PyInstaller 构建和敏感信息扫描通过。
10. 安装包版本、文件名和 `VERSION` 一致，并生成 SHA256。

## 非目标

- 首版不提供应用内自动下载或静默更新。
- 首版不迁移到 Electron 或重写现有前端。
- 首版不制作 macOS/Linux 桌面安装包。
- 首版不把外部 CLI 登录态或当前开发机个人数据打入安装包。
