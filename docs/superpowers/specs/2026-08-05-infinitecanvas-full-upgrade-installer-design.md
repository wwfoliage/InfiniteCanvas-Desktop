# InfiniteCanvas 完整升级安装包设计

## 目标

发布一个完整的 Windows 安装包，同一个安装包同时支持：

- 未安装 InfiniteCanvas 的电脑直接首次安装；
- 已安装任意旧版本的电脑直接覆盖升级；
- 升级时移除旧程序运行库残留，避免旧 Python 包干扰新版；
- 始终保留画布、素材、API 配置、应用设置、日志和下载设置等用户数据。

本次修正版版本号为 `2026.08.05`。

## 已确认故障

`2026.08.04` 安装包只覆盖同名文件，没有清理旧安装目录。旧版留下的
`_internal/websockets` 和 `websockets-16.1.1.dist-info` 只有 Python 3.10 的二进制
扩展，没有完整包代码。新版 Python 3.11 运行时把该目录识别为不完整命名空间，导致
Uvicorn 启动时报 `cannot import name '__version__' from 'websockets'`。

## 安装与升级行为

安装程序继续使用现有稳定 `AppId`，因此 Windows 将新版识别为同一应用的升级。

在复制新版文件之前，安装程序删除安装目录中的旧程序运行内容：

- `{app}\_internal` 整个目录；
- `{app}\InfiniteCanvas.exe` 主程序文件。

随后从安装包复制完整的新主程序和 `_internal` 运行库。首次安装时上述路径不存在，
清理操作应安全跳过，因此同一个包可以在没有 InfiniteCanvas 的电脑上直接安装。

安装程序不清空整个 `{app}`，保留 Inno Setup 的卸载器记录和安装器管理文件。用户已
确认不会在程序安装目录中保存自定义文件。

## 用户数据边界

升级和卸载逻辑不得删除或改写 `%LOCALAPPDATA%\InfiniteCanvas`。该目录中的以下内容
必须跨版本保留：

- `app_settings.json` 及主题、缩放、语言、下载目录设置；
- API 和 ComfyUI 配置；
- 画布、项目、历史记录和素材；
- 日志、缓存目录及其他运行期数据。

程序文件与用户数据继续保持分离：安装目录只放只读运行文件，可写数据只放用户数据
目录。

## 安全与错误处理

- 安装器使用 `CloseApplications=yes`，复制前要求正在运行的 InfiniteCanvas 退出。
- 旧运行目录清理只作用于解析后的 `{app}`，不接受网页或用户数据传入任意路径。
- 如果旧运行目录无法删除，安装应失败并显示错误，不能继续生成混合版本目录。
- 保持每用户安装和最低权限，不要求管理员权限。
- 不引入自动后台更新；用户仍手动下载并运行完整新版安装包。

## 测试与验收

自动化测试覆盖：

1. 安装脚本声明升级前清理 `_internal` 和主程序。
2. 安装脚本不包含 `%LOCALAPPDATA%\InfiniteCanvas` 删除规则。
3. 首次安装到空目录成功，主程序可启动。
4. 在旧安装目录预置不完整 `websockets` 残留后覆盖安装，残留文件被删除，主程序可启动。
5. 在隔离用户数据目录写入哨兵文件，覆盖升级后文件内容保持不变。
6. 启动后只出现 PyWebView 桌面窗口，不打开浏览器或 CMD，关闭后无残留进程。

构建完成后运行发布扫描，生成安装包、`SHA256SUMS.txt` 和发布清单，并将最终文件整理到
`E:\codex\发布安装包\InfiniteCanvas\2026.08.05`。

## 后续发布规则

以后每个版本都发布完整安装包，不发布只能依附旧版本的差分补丁。用户只需运行更高
版本安装包即可升级；新电脑也可以使用同一个安装包首次安装。
