# 智能画布 `@` 输入源与可见参考栏一致设计

日期：2026-08-02

## 背景

智能画布此前把 `@` 输入源收紧为仅包含直接连线媒体，成功排除了更前面的祖先节点、其他分支和未连线节点，但也误删了当前生成节点自身已经产出的图片或视频。界面红框参考栏仍能显示这些当前节点媒体，因此出现“参考栏里看得到，却无法 `@`”的不一致。

## 目标行为

`@` 弹窗的“输入源”标签与当前节点红框参考栏使用同一个可见媒体集合：

- 当前节点已经产出的图片或视频，只要显示在参考栏中，就能被 `@`；
- 直接连线节点传入、并显示在参考栏中的图片或视频能被 `@`；
- 用户已经明确加入参考栏的手动参考或资产引用能被 `@`；
- 更前面的祖先节点、其他分支和未连线画布节点不出现在参考栏时，也不出现在 `@` 输入源中；
- 资产库标签维持现有独立浏览和选择行为。

## 实现设计

`inputMentionCandidateImages(node)` 不再单独读取 `directConnectedMediaFor(node)`，而是读取 `visibleReferenceImagesFor(node)`。后者已经统一组合当前节点允许的自身参考、直接上游参考、手动参考和已授权提示词引用，并通过既有授权逻辑拦截祖先或未连线画布来源。

候选列表继续：

- 丢弃没有 URL 的条目；
- 按 URL 去重；
- 为每个候选生成显示别名与临时 mention ID；
- 保留图片和视频类型信息。

生图、生视频的请求构建和 `isAllowedMentionReference` 授权规则不做放宽。当前节点媒体本来已经能通过自身 URL 校验；本次只修复它在 UI 候选列表中的缺失。因此，能看到并选择当前节点自产媒体，不会让祖先或未连线节点重新进入 API 请求。

## 数据流

1. 用户在当前生成节点输入框键入 `@`。
2. 输入源候选调用 `visibleReferenceImagesFor(node)`。
3. 可见参考集合经过 URL 有效性过滤和 URL 去重。
4. 用户选择候选后，提示词保存媒体标记。
5. 运行时仍由共享请求授权再次校验并去重后上传。

## 测试

回归测试覆盖：

1. `inputMentionCandidateImages` 复用 `visibleReferenceImagesFor`，不再直接读取递归或裸连线集合。
2. 当前节点自产图片和视频出现在 `@` 输入源中。
3. 直接连线图片和视频仍然出现。
4. 同一 URL 同时来自自身与直接连线时只出现一次。
5. 祖先节点、其他分支和未连线节点仍被排除。
6. 共享请求授权测试继续验证祖先和未连线媒体不会上传，资产库明确 `@` 的素材仍可上传。

## 非目标

- 不改变红框参考栏本身的组成规则。
- 不改变资产库的分类、注册或选择界面。
- 不改变提示词文本传递、循环工作流或引用数量上限。
- 不新增分类标签或其他 UI 控件。
